## What's done

**Stage 2 (`stage2_world/`):** parametric, seeded, deterministic synthetic
world generator. 35 posts × 30 SKUs × 3 years × stock dynamics = 2.35M rows.
Public-source calibration anchors documented inline. Validation report passes.

**Stage 3 (`stage3_models/`):** ML model layer + risk composition.
- 54 quantile XGBoost demand forecasters (band × head × q10/q50/q90)
- 20 binary XGBoost route classifiers (pass × 1/3/7/14d horizon)
- 1 rule-based Weibull vehicle reliability scorer
- 1 composed risk scorer producing StockoutRisk rows

End-to-end: training in ~57s, prediction snapshot in ~7s.

Honest reporting in `stage3_models/reports/evaluation_report.md`. The
masterplan's "MAPE < 20% on top-30 SKUs" target is **not met as written**
(weighted-avg MAPE 29%); MAE-relative-to-median framing argues the model is
acceptable on forward SKUs (0.14–0.25 ratio). Both numbers in the talk track.

Vehicle scorer Brier skill ≈ 0 — documented weak signal, per the masterplan's
prediction.

## What's not done

**Stage 4 — Optimizer (Component 4):** OR-Tools MIP reading the four Stage 3
output parquets. Not started.

**Stage 5 — Lineage views + UI (Components 5/6):** SQL views joining alerts →
risks → forecasts → models → snapshots. Decision on visibility layer
deferred to v4 of the masterplan.

**Ontology in Postgres (Component 1):** Currently the "ontology" is the
parquet schema. Migration to Supabase Postgres + PostGIS is the next
infrastructure step.

## Working conventions

1. **Code is full files, not diffs.** Stage 2 and Stage 3 modules are
   complete and self-contained. Don't ship patches.
2. **Synthetic data has provenance.** Every parameter in `stage2_world/config.py`
   is either anchored to a public source (cited in `stage2_world/README.md`)
   or flagged `SYNTHETIC-INFERRED`. Honor this discipline in new modules.
3. **Lineage on every row.** Every prediction row in Stage 3 outputs carries
   `model_version`, `snapshot_date`, `generated_at`, `data_snapshot_seed`.
   Stage 4 should preserve this.
4. **Honest evaluation.** Report numbers as they are. Flag weak signals.
   Surface MAPE *and* MAE-relative-to-median. Don't pick the favorable framing.
5. **No technical instructions for Eshan to run.** Deliverables are
   files / hosted artifacts. Eshan does not run code locally.

## Data flow

```
stage2_world/data/*.parquet  (generated by stage2_world/generate.py)
         │
         ▼
stage3_models/  reads via config.DATA_DIR (defaults to ../stage2_world/data/)
         │     train.py:           reads parquets → writes models/ + reports/
         │     predict_service.py: reads parquets + models/ → writes output/snapshot_*/
         ▼
output/snapshot_<date>/{demand_forecasts, route_predictions, vehicle_reliability, stockout_risk}.parquet
         │
         ▼
[Stage 4 optimizer — TBD]
```

The `BASTION_DATA_DIR` environment variable can override the Stage 2 data
path (e.g. to point at a freshly regenerated world without modifying config).
